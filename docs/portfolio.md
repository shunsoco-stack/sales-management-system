## 解決する課題

- 表計算や複数ツールへ分散した取引、顧客、商品、担当者、店舗、目標を一元化する
- 割引、複数税率、取消、返金を含む売上を一貫した計算規則で記録する
- 登録データを KPI、前期間比、目標差、粗利、顧客行動へ変え、意思決定へつなげる
- 組織・店舗・担当範囲を越えた閲覧や、取消済み取引の改変を防ぐ
- CSV 移行前に列・参照・金額の不備を可視化する

## 主な機能

- Firebase メール／パスワード認証、新規組織登録、ログアウト、パスワード再設定
- 登録不要・ブラウザ分離型のデモログイン、4 ロール切替、初期データ復元
- 最大 2 明細の売上登録・編集、整数円計算、取消、全額／一部返金、複製、印刷、更新履歴
- キーワードと期間・店舗・担当者・商品・支払方法・金額・状態を組み合わせた売上検索
- 期間連動 KPI、売上・件数・平均客単価、支払方法構成、目標差・目標ペース・前期間比
- 商品・サービス、顧客、担当者、店舗、売上目標の管理。担当者の業務ロールは表示用で Firebase ユーザー権限とは非連動
- 担当者、商品・カテゴリ、顧客、店舗、支払方法の分析
- 日報・月報とブラウザ印刷
- 売上、顧客、商品、担当者別、店舗別 CSV 出力
- 売上、商品、顧客 CSV の全行検証、既存／入力内重複、2 明細上限、商品原価の検証、エラー行表示、登録前プレビュー
- 組織・店舗スコープ、4 ロール、Firestore Security Rules、追記専用監査ログ

## 工夫したポイント

### 1. 入力から経営判断まで同じデータ定義

登録画面、一覧、ダッシュボード、分析、目標、レポートが同じ純売上ポリシーと期間条件を使います。期間切替時は売上・件数・平均客単価・目標ペースとグラフが連動し、見た目だけのダッシュボードにならないようにしました。

### 2. 金額を整数円で扱う

浮動小数の通貨計算を避け、税率は basis points で保持します。各明細で「小計 → 割引 → 税を 1 円未満切捨て → 合計」を計算し、取引単位で税を再丸めしません。取消・全額返金・未確定は純売上 0 円、一部返金は残額だけを認識します。返金配賦の端数は最後の明細へ集約して合計を完全一致させ、粗利率は税抜認識売上を分母にします。

### 3. 操作履歴を失わない

売上は物理削除せず、理由付き取消または返金として状態遷移を残します。Firestore 書込では対象ドキュメントと監査ログを同一バッチにし、Rules の `getAfter()` で対応関係を検証します。

### 4. 安全なポートフォリオデモ

デモは Firebase を初期化せず、バージョン付きデータを閲覧者の `localStorage` にだけ保存します。共有データを壊さず売上登録・編集・分析・CSV を体験でき、設定画面から初期状態へ戻せます。

### 5. 情報量を整理する Apple Design

システムフォント、明確な階層、余白、44px 操作領域、即時フィードバック、控えめな素材表現を採用しました。数値には tabular figures、状態には文字とアイコン、モバイル表にはカード表示を使い、装飾より比較と操作性を優先しています。reduced motion / transparency / contrast にも対応します。

## セキュリティ

- Firebase Authentication と認証状態監視
- `organizationId` と `allowedLocationIds` によるテナント・店舗分離
- 管理者、マネージャー、一般、閲覧のみの画面・ドメイン・Rules 制御
- 一般ユーザーは `users.staffId` と売上の `staffId` が一致する取引だけを操作
- 取消・返金を管理者に限定し、取消済み・全額返金済み取引をロック
- 数量 × 単価、明細別切捨て税、親合計、金額・数量・税率・2 明細上限の Rules 検証
- 対象変更と監査ログの同一バッチ、更新前時刻による CAS、返金累計の単調増加、監査ログの更新・削除禁止
- CSV 数式注入対策
- Hosting の `nosniff`、frame deny、Referrer Policy、Permissions Policy

## データ設計

主要コレクションは `organizations`、`users`、`locations`、`staff`、`customers`、`categories`、`products`、`paymentMethods`、`sales`、`goals`、`settings`、`auditLogs` です。売上明細は `sales.items[]` へ埋め込み、取引と明細の金額を一括で読み取ります。seed は平坦な `saleItems` と `dailySummaries` / `monthlySummaries` も生成しますが、現在の画面集計は最大 1,000 売上の購読スナップショットをブラウザで集計します。

## 実装上の現在の制約

- 1 取引の明細は最大 2 件。Rules 内で明細式と親合計を厳密検証する現行境界
- 公開デモはVercelへデプロイ済み。Firebase本番プロジェクトは未設定で、公開URLではブラウザ内デモのみ提供
- Firestore 画面集計は 1,000 売上の購読上限内
- 日次・月次集計は seed のみで、通常の売上操作では自動更新しない
- Firebase モードの顧客購入指標を Firestore へ永続更新するサーバー処理は未実装。画面は購読中売上から派生値を再計算
- 実ユーザー招待・ロール変更、カテゴリ・支払方法管理の UI は未実装
- PDF ファイル生成は未実装。日報・月報はブラウザ印刷
- 売上一覧 CSV と売上インポート CSV は用途・粒度が異なり、直接往復できない
- Firebase の売上 CSV 取込は 4 売上ごとに commit し、ファイル全体では原子的でない
